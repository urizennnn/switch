A field guide

The TUI stack, finally
explained the way you think.

Bubble Tea, Bubbles, and Lip Gloss are three packages that build terminal interfaces — but the official docs are reference, not teaching. This guide is teaching. Every feature is shown the way you'd actually use it: a one-line description of what it's for, a minimal example that runs, and a note on when to reach for it.

The framework
Bubble Tea
The event loop. State, updates, render. Like Elm or React, for terminals.
The widgets
Bubbles
Pre-built components — text input, viewport, list, spinner. Drop them in.
The styling
Lip Gloss
CSS for strings. Colors, borders, padding, layout. Pure string in, styled string out.
Mental Model

How the three packages fit together

Once you see this picture, the rest of the framework collapses into common sense. Each package owns one thing, and they only talk through strings.

Bubble Tea drives the event loop // you write Init/Update/View │ ▼ calls your View() │ ▼ which assembles strings using ─► Lip Gloss // styles, joins, borders │ ▲ ▼ │ uses widgets from ──────────────► Bubbles // each widget renders with Lip Gloss │ ▼ each Bubble has its own Init / Update / View — they are nested Bubble Tea models.

The cleanest way to think about it: Bubble Tea is the loop, Lip Gloss is the paint, Bubbles are pre-painted widgets. You can use Lip Gloss without Bubble Tea (just to color a string). You can use Bubble Tea without Bubbles (write your own widgets). But you cannot use Bubbles without both — every Bubble is a tiny Bubble Tea model that paints itself with Lip Gloss.

Package one of three

Bubble Tea — the framework

The Elm Architecture, in Go. Your app is a function: (state, event) → (new state, command). Bubble Tea handles the loop. You write three methods.

The Architecture

Every Bubble Tea program is a struct that satisfies tea.Model:

type Model interface {
              Init() Cmd
              Update(Msg) (Model, Cmd)
              View() string
              }

The runtime calls them in this order, forever:

  1. Init runs once when the program starts. Returns the first command (e.g. "fetch initial data").
  2. Update runs every time something happens — a keypress, a window resize, a tick, a network response. Returns a new model and an optional command.
  3. View runs after every Update. Returns the string to draw on screen.

That's it. Everything in Bubble Tea — every animation, every API call, every keystroke — is just a Msg flowing into Update.

Why this matters

You never call Update or View yourself. The runtime does. You only describe what should happen for each kind of message. State flows in one direction, which is why this scales.

Model — your application's state

The model is just a struct. Put everything your app needs to remember in it.

type model struct {
              messages []string
              input string
              cursor int
              err error
              }

              func initialModel() model {
              return model{
              messages: []string{},
              input: "",
              }
              }

Two questions to ask when designing the model:

  • If this changed, would the screen look different? → put it in the model.
  • Is this only used inside one function? → keep it as a local variable.

Init — the first command

Runs once. Returns a tea.Cmd (or nil if there's nothing to do at startup).

func (m model) Init() tea.Cmd {
              // Return nil if nothing needs to run on startup
              return nil
              }

              // Or kick off something:
              func (m model) Init() tea.Cmd {
              return tea.Batch(
              loadConfig(), // your custom Cmd
              spinner.Tick, // start the spinner
              )
              }
Use Init for

Loading initial data, starting timers, focusing an input on launch, requesting the window size early.

Update — your reducer

Receives every message in the system. Switch on the type, mutate the model, return it.

func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              switch msg := msg.(type) {

              case tea.KeyMsg:
              switch msg.String() {
              case "ctrl+c", "q":
              return m, tea.Quit
              case "enter":
              m.messages = append(m.messages, m.input)
              m.input = ""
              return m, nil
              }

              case tea.WindowSizeMsg:
              m.width = msg.Width
              m.height = msg.Height
              return m, nil
              }

              return m, nil
              }

Two contracts you must respect:

  • Always return a model. Even if nothing changed, return m.
  • Return a Cmd if you want side effects. Never make HTTP calls or read files directly inside Update — wrap them in a Cmd. The runtime executes commands off-thread.
Common pitfall

Calling http.Get directly inside Update will block the entire UI. Wrap it in a tea.Cmd. See Commands.

View — render to a string

Pure function. Read the model, return a string. No side effects, no commands.

func (m model) View() string {
              var b strings.Builder

              b.WriteString("Messages:\n\n")
              for _, msg := range m.messages {
              b.WriteString(" · " + msg + "\n")
              }

              b.WriteString("\n> " + m.input)
              return b.String()
              }

The runtime diffs your output and only redraws what changed. You don't optimize this — just return the full string every time.

Messages — what flows into Update

A tea.Msg is just interface{}. Any type can be a message. Bubble Tea ships with these built-ins:

Message When it fires
tea.KeyMsg Every keypress. Use msg.String() for "ctrl+c", "enter", "a", etc.
tea.MouseMsg Mouse events (only if mouse mode enabled).
tea.WindowSizeMsg Terminal resized. Has .Width and .Height.
tea.QuitMsg Sent before the program exits.
tea.FocusMsg / tea.BlurMsg Terminal gained/lost focus.

Custom messages

Define your own types to communicate between async work and Update:

type chatLoadedMsg struct{ messages []Message }
              type errMsg struct{ err error }

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              switch msg := msg.(type) {
              case chatLoadedMsg:
              m.messages = msg.messages
              case errMsg:
              m.err = msg.err
              }
              return m, nil
              }

Commands — async, the right way

A tea.Cmd is just a function: func() tea.Msg. The runtime calls it in a goroutine, then routes the returned message back into Update.

func loadChat(id string) tea.Cmd {
              return func() tea.Msg {
              chat, err := api.GetChat(id)
              if err != nil {
              return errMsg{err}
              }
              return chatLoadedMsg{chat.Messages}
              }
              }

              // Usage in Update:
              case tea.KeyMsg:
              if msg.String() == "enter" {
              return m, loadChat(m.selectedID)
              }

This is the entire pattern for HTTP calls, DB queries, file I/O, anything that takes time:

  1. Define a custom Msg type for the result.
  2. Return a tea.Cmd that does the work and returns that message.
  3. Handle the message in Update and update state.
Mental model

Cmds say "do this thing, then send me a message when you're done." Update never blocks. The UI never freezes.

Batch & Sequence — multiple commands

tea.Batch runs commands in parallel. tea.Sequence runs them in order.

// Run two things at once:
              return m, tea.Batch(
              loadMessages(),
              spinner.Tick,
              )

              // Run in order (rare — most things should be parallel):
              return m, tea.Sequence(
              saveDraft(),
              sendMessage(),
              )

Built-in helpers you'll see often:

  • tea.Quit — exits the program.
  • tea.Tick(time.Second, fn) — fires a message after a delay.
  • tea.Every(time.Second, fn) — fires repeatedly. Used by spinners and clocks.
  • tea.Println("...") — prints above the running TUI without disturbing it.
  • tea.ClearScreen — wipes the screen.

Program options

You start a Bubble Tea app by creating a tea.Program. Options control terminal behaviour:

p := tea.NewProgram(
              initialModel(),
              tea.WithAltScreen(), // Full-screen mode (recommended)
              tea.WithMouseCellMotion(), // Enable mouse events
              )

              if _, err := p.Run(); err != nil {
              log.Fatal(err)
              }
Option Effect
WithAltScreen() Uses the alternate screen buffer. App is full-screen and your shell's history is preserved on exit.
WithMouseCellMotion() Mouse motion + clicks → tea.MouseMsg.
WithMouseAllMotion() Like above but reports motion even when no button is pressed.
WithoutSignalHandler() Don't auto-handle SIGINT. You handle ctrl+c yourself.
WithInput(r io.Reader) Read input from somewhere other than stdin (e.g. testing).
WithOutput(w io.Writer) Write output somewhere other than stdout.

Composition — child models

Big apps are made of small models. The parent embeds children, and forwards messages to them.

type model struct {
              input textinput.Model // a child model from Bubbles
              viewport viewport.Model
              focused string // "input" or "viewport"
              }

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              var cmds []tea.Cmd
              var cmd tea.Cmd

              switch msg := msg.(type) {
              case tea.KeyMsg:
              if msg.String() == "tab" {
              m.focused = toggle(m.focused)
              return m, nil
              }
              }

              // Forward to whichever child has focus.
              if m.focused == "input" {
              m.input, cmd = m.input.Update(msg)
              cmds = append(cmds, cmd)
              } else {
              m.viewport, cmd = m.viewport.Update(msg)
              cmds = append(cmds, cmd)
              }

              return m, tea.Batch(cmds...)
              }

              func (m model) View() string {
              return lipgloss.JoinVertical(lipgloss.Left,
              m.viewport.View(),
              m.input.View(),
              )
              }

Two rules for composition:

  • The parent decides which child gets the message. Most parents forward keypresses only to the focused child.
  • Window-size, ticks, and custom messages should usually be forwarded to all children — they all need to know.

Sending messages from outside

Sometimes you need a goroutine — a websocket reader, a queue consumer — to push messages into the program. Use p.Send():

p := tea.NewProgram(initialModel())

              // In another goroutine (e.g. a websocket reader):
              go func() {
              for ev := range websocket.Events() {
              p.Send(eventMsg{ev})
              }
              }()

              if _, err := p.Run(); err != nil { log.Fatal(err) }

This is how you pipe arbitrary external events (server-sent events, file watchers, IPC) into the model.

Package two of three

Bubbles — pre-built widgets

Each Bubble is a complete Bubble Tea model: it has its own state, its own Update, its own View. You embed it in your model and forward messages to it. Eleven essential widgets, used the same way every time.

The pattern

Every Bubble follows the same three-step usage: (1) store it in your model, (2) forward messages to it in Update, (3) call .View() in your View. Once you see it once, you've seen them all.

textinput — single-line text field

For chat composers, search bars, login fields. One line, with cursor and placeholder.

import "github.com/charmbracelet/bubbles/textinput"

              type model struct { ti textinput.Model }

              func newModel() model {
              ti := textinput.New()
              ti.Placeholder = "Type a message..."
              ti.Focus()
              ti.CharLimit = 280
              ti.Width = 50
              return model{ti}
              }

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              var cmd tea.Cmd
              m.ti, cmd = m.ti.Update(msg)
              return m, cmd
              }

              func (m model) View() string { return m.ti.View() }

Useful methods: .Value() to read text, .SetValue("") to clear, .Focus()/.Blur() for focus, .Focused() to check.

textarea — multi-line input

Like textinput, but multiline. For commit messages, longer composing, code input.

import "github.com/charmbracelet/bubbles/textarea"

              ta := textarea.New()
              ta.Placeholder = "Write a message..."
              ta.Focus()
              ta.SetWidth(60)
              ta.SetHeight(5)
              ta.ShowLineNumbers = false

Useful methods: .Value(), .SetValue(s), .LineCount(), .LineInfo() for cursor position.

viewport — scrollable region

This is the workhorse for chat windows, log readers, file viewers. Give it a chunk of pre-rendered text; it handles scrolling.

import "github.com/charmbracelet/bubbles/viewport"

              vp := viewport.New(80, 20) // width, height
              vp.SetContent(longString)

              // In Update — viewport handles its own keys (j/k, pgup/pgdn, etc.):
              m.vp, cmd = m.vp.Update(msg)

              // To re-set content (e.g. on new message):
              m.vp.SetContent(renderMessages(m.messages))
              m.vp.GotoBottom() // scroll to last line

Useful methods: .GotoBottom(), .GotoTop(), .LineUp(n), .LineDown(n), .SetContent(s), .AtBottom() (useful to decide whether to auto-scroll on new content).

Use viewport for

Anything that might overflow the visible area: chat history, log streams, markdown rendering, file diffs.

list — selectable list with filter

The most opinionated Bubble. Built-in keyboard navigation, filtering with /, status messages, pagination. Good for inboxes, file pickers, any "pick one of many" UI.

import "github.com/charmbracelet/bubbles/list"

              type item struct{ title, desc string }

              func (i item) Title() string { return i.title }
              func (i item) Description() string { return i.desc }
              func (i item) FilterValue() string { return i.title }

              items := []list.Item{
              item{"Alice", "Hey, are you free?"},
              item{"Bob", "Sent the design"},
              }

              l := list.New(items, list.NewDefaultDelegate(), 40, 20)
              l.Title = "Inbox"

Useful methods: .SelectedItem(), .Index(), .SetItems(items), .SetSize(w, h), .SetFilteringEnabled(true).

Customization: list.NewDefaultDelegate() renders title + description. Implement list.ItemDelegate yourself for fully custom rows.

table — selectable rows + columns

For dashboards, data views. Has navigation, focus styling, customizable styles.

import "github.com/charmbracelet/bubbles/table"

              cols := []table.Column{
              {Title: "Service", Width: 16},
              {Title: "Status", Width: 10},
              {Title: "Latency", Width: 10},
              }

              rows := []table.Row{
              {"api", "up", "12ms"},
              {"worker-1", "up", "8ms"},
              {"db", "down", "—"},
              }

              t := table.New(
              table.WithColumns(cols),
              table.WithRows(rows),
              table.WithFocused(true),
              table.WithHeight(8),
              )

Useful methods: .SelectedRow(), .Cursor(), .SetRows(rows), .MoveUp(n), .MoveDown(n).

spinner — loading indicator

The animated ⠋ ⠙ ⠹ ⠸ spinner. Tiny, but it's how the user knows something's happening.

import "github.com/charmbracelet/bubbles/spinner"

              s := spinner.New()
              s.Spinner = spinner.Dot
              s.Style = lipgloss.NewStyle().Foreground(lipgloss.Color("#FF7849"))

              // In Init — start ticking:
              func (m model) Init() tea.Cmd { return m.spinner.Tick }

              // In Update — keep it animated:
              case spinner.TickMsg:
              m.spinner, cmd = m.spinner.Update(msg)
              return m, cmd

              // In View:
              return m.spinner.View() + " loading..."

Built-in styles: spinner.Dot, .Line, .MiniDot, .Jump, .Pulse, .Points, .Globe, .Moon, .Monkey, .Meter, .Hamburger.

Don't forget

If you don't return m.spinner.Tick from Init (or as a Cmd from Update), the spinner will not animate. It needs ticks to advance frames.

progress — progress bar

For determinate progress (downloads, uploads, file processing).

import "github.com/charmbracelet/bubbles/progress"

              p := progress.New(progress.WithDefaultGradient())
              p.Width = 40

              // Animate to 60%:
              cmd := m.p.SetPercent(0.6)

              // In Update — progress sends FrameMsg during animation:
              case progress.FrameMsg:
              pm, cmd := m.p.Update(msg)
              m.p = pm.(progress.Model)
              return m, cmd

              // View:
              return m.p.View()

Variants: WithDefaultGradient(), WithSolidFill("#5fc5b0"), WithGradient(from, to), WithoutPercentage().

paginator — page indicator

Renders ● ○ ○ ○ dots or 1/4 labels. Tracks pagination state for paginated lists. 

import "github.com/charmbracelet/bubbles/paginator"

              p := paginator.New()
              p.Type = paginator.Dots
              p.PerPage = 10
              p.SetTotalPages(len(items))

              // Get the slice for the current page:
              start, end := p.GetSliceBounds(len(items))
              visible := items[start:end]

              // Render:
              return p.View()

key — keybinding declarations

Not a UI widget — but central. Defines named keybindings with help text. Pairs with the help bubble.

import "github.com/charmbracelet/bubbles/key"

              type keyMap struct {
              Up key.Binding
              Down key.Binding
              Enter key.Binding
              Quit key.Binding
              }

              var keys = keyMap{
              Up: key.NewBinding(key.WithKeys("up", "k"), key.WithHelp("↑/k", "up")),
              Down: key.NewBinding(key.WithKeys("down", "j"), key.WithHelp("↓/j", "down")),
              Enter: key.NewBinding(key.WithKeys("enter"), key.WithHelp("⏎", "select")),
              Quit: key.NewBinding(key.WithKeys("q", "ctrl+c"), key.WithHelp("q", "quit")),
              }

              // Match in Update:
              case tea.KeyMsg:
              switch {
              case key.Matches(msg, keys.Up): m.cursor--
              case key.Matches(msg, keys.Down): m.cursor++
              case key.Matches(msg, keys.Quit): return m, tea.Quit
              }
Why bother?

Two reasons: (1) you can disable bindings dynamically with .SetEnabled(false), (2) the help bubble auto-generates a help bar from these declarations.

help — auto-generated help bar

The ctrl+a approve · ctrl+r reject · ? help footer at the bottom of polished TUIs. Reads your key.Bindings and renders them.

import "github.com/charmbracelet/bubbles/help"

              // Implement the help.KeyMap interface on your keymap:
              func (k keyMap) ShortHelp() []key.Binding {
              return []key.Binding{k.Up, k.Down, k.Enter, k.Quit}
              }
              func (k keyMap) FullHelp() [][]key.Binding {
              return [][]key.Binding{
              {k.Up, k.Down},
              {k.Enter, k.Quit},
              }
              }

              h := help.New()

              // In View:
              return mainContent + "\n" + h.View(keys)

              // Toggle expanded help on "?":
              case key.Matches(msg, keys.Help):
              m.help.ShowAll = !m.help.ShowAll

filepicker — pick a file from disk

A directory browser. Returns the selected file path.

import "github.com/charmbracelet/bubbles/filepicker"

              fp := filepicker.New()
              fp.AllowedTypes = []string{".md", ".txt"}
              fp.CurrentDirectory, _ = os.UserHomeDir()

              // In Update:
              m.fp, cmd = m.fp.Update(msg)
              if didSelect, path := m.fp.DidSelectFile(msg); didSelect {
              m.selectedFile = path
              }

stopwatch & timer

Two small bubbles for time. stopwatch counts up, timer counts down.

import (
              "github.com/charmbracelet/bubbles/stopwatch"
              "github.com/charmbracelet/bubbles/timer"
              )

              sw := stopwatch.NewWithInterval(time.Millisecond * 100)
              t := timer.NewWithInterval(5*time.Minute, time.Second)

              // In Init:
              return tea.Batch(m.sw.Init(), m.t.Init())

              // In Update — forward StartStopMsg, TickMsg, etc:
              m.sw, cmd = m.sw.Update(msg)
              m.t, c2 := m.t.Update(msg)

              // View:
              return m.sw.View() + " · " + m.t.View()
Package three of three

Lip Gloss — CSS for strings

Pure string-in, string-out. You build a Style, you call .Render(s), you get a styled string with ANSI escape codes baked in. That string can go anywhere — printed, joined, written to a file. Lip Gloss never touches the terminal directly.

Style — the core type

Everything in Lip Gloss starts with NewStyle(). Methods return a new style — they chain.

import "github.com/charmbracelet/lipgloss"

              style := lipgloss.NewStyle().
              Foreground(lipgloss.Color("#FF7849")).
              Background(lipgloss.Color("#11151D")).
              Bold(true).
              Padding(1, 2).
              Border(lipgloss.RoundedBorder())

              fmt.Println(style.Render("Hello"))

Styles are immutable. Each method returns a fresh style. You can store partial styles and reuse them.

var (
              base = lipgloss.NewStyle().Padding(0, 1)
              primary = base.Foreground(lipgloss.Color("#FF7849"))
              danger = base.Foreground(lipgloss.Color("#ED6A5E")).Bold(true)
              )

Colors

Three color types, picked for different scenarios.

Type Use when
Color("#FF7849") Always render this exact color. Hex, ANSI 256, or ANSI 16.
AdaptiveColor{Light, Dark} Pick based on terminal background — light mode users get one color, dark mode gets another.
CompleteColor{TrueColor, ANSI256, ANSI} Specify the same color in three formats. Lip Gloss picks the best for the terminal's capabilities. 
// Static
              lipgloss.Color("#FF7849") // hex
              lipgloss.Color("205") // ANSI 256
              lipgloss.Color("9") // ANSI 16 (red)

              // Adapts to light/dark terminals
              lipgloss.AdaptiveColor{
              Light: "#1F2937",
              Dark: "#E5E7EB",
              }

              // Best of all worlds
              lipgloss.CompleteColor{
              TrueColor: "#FF7849",
              ANSI256: "208",
              ANSI: "3",
              }

Apply with .Foreground(c) and .Background(c).

Text formatting

lipgloss.NewStyle().
              Bold(true).
              Italic(true).
              Underline(true).
              Strikethrough(true).
              Reverse(true). // swap fg/bg
              Blink(true). // rarely supported
              Faint(true). // dim
              Render("formatted")

All booleans. All chainable. Apply only what you need.

Padding & margin

CSS-style. Padding is inside the box, margin is outside.

// All four sides
              .Padding(2)

              // Vertical, horizontal
              .Padding(1, 2) // 1 top/bottom, 2 left/right

              // Top, right, bottom, left (CSS shorthand)
              .Padding(1, 2, 3, 4)

              // Individual
              .PaddingTop(1).PaddingLeft(2)

              // Margin works the same
              .Margin(1, 2)
              .MarginTop(1)

Borders

Built-in border styles, or define your own characters.

.Border(lipgloss.NormalBorder())
              .Border(lipgloss.RoundedBorder()) // ╭─╮ ╰─╯
              .Border(lipgloss.ThickBorder()) // ┏━┓ ┗━┛
              .Border(lipgloss.DoubleBorder()) // ╔═╗ ╚═╝
              .Border(lipgloss.HiddenBorder()) // takes up space, invisible

              // Only some sides:
              .Border(lipgloss.NormalBorder(), true, false, true, false)
              // top right bottom left

              // Border color (independent of fg):
              .BorderForeground(lipgloss.Color("#FF7849"))

              // Custom:
              b := lipgloss.Border{
              Top: "─", Bottom: "─", Left: "│", Right: "│",
              TopLeft: "╭", TopRight: "╮", BottomLeft: "╰", BottomRight: "╯",
              }
              .Border(b)

Width & height

Force a string to a specific size. Pads or wraps as needed.

.Width(40) // exactly 40 cells wide
              .Height(10) // exactly 10 lines tall
              .MaxWidth(80) // wrap if longer
              .MaxHeight(20) // truncate if taller

Combined with padding/borders, this is how you build fixed-size panes:

pane := lipgloss.NewStyle().
              Width(40).
              Height(20).
              Border(lipgloss.RoundedBorder()).
              Padding(1, 2)
Width gotcha

.Width() is the inner width — it does not include border or margin. Total cells used = Width + horizontal padding + 2 (border) + horizontal margin.

Alignment

.Align(lipgloss.Center) // both axes
              .AlignHorizontal(lipgloss.Right)
              .AlignVertical(lipgloss.Bottom)

              // Constants:
              // lipgloss.Left, .Center, .Right
              // lipgloss.Top, .Center, .Bottom

Alignment requires a .Width() (for horizontal) or .Height() (for vertical) to have something to align inside.

Joining strings — the layout primitive

This is how you build multi-pane layouts. Two functions, used everywhere.

// Side by side. Second arg = vertical alignment of items.
              lipgloss.JoinHorizontal(lipgloss.Top, sidebar, content, panel)

              // Stacked. Second arg = horizontal alignment.
              lipgloss.JoinVertical(lipgloss.Left, header, body, footer)

Example: a three-pane chat app

func (m model) View() string {
              sidebar := paneStyle.Width(24).Height(m.height-2).Render(m.sidebar.View())
              chat := paneStyle.Width(m.width-24-30).Height(m.height-2).Render(m.chat.View())
              info := paneStyle.Width(30).Height(m.height-2).Render(m.info.View())

              body := lipgloss.JoinHorizontal(lipgloss.Top, sidebar, chat, info)

              return lipgloss.JoinVertical(lipgloss.Left, body, m.statusbar.View())
              }

Place — center anything

Drops a string at a position inside a larger box. Perfect for splash screens and modals.

// Center horizontally and vertically in a 80×24 area:
              lipgloss.Place(80, 24,
              lipgloss.Center, lipgloss.Center,
              "✦ Welcome to switch ✦",
              )

              // Or one axis at a time:
              lipgloss.PlaceHorizontal(80, lipgloss.Right, "→")
              lipgloss.PlaceVertical(24, lipgloss.Bottom, "status: ok")

Tables

Lip Gloss includes a table subpackage for static tables (different from the interactive Bubbles table).

import "github.com/charmbracelet/lipgloss/table"

              t := table.New().
              Border(lipgloss.RoundedBorder()).
              BorderStyle(lipgloss.NewStyle().Foreground(lipgloss.Color("#5FC5B0"))).
              Headers("SERVICE", "STATUS", "LATENCY").
              Rows(
              []string{"api", "up", "12ms"},
              []string{"db", "down", "—"},
              ).
              StyleFunc(func(row, col int) lipgloss.Style {
              if row == 0 { return headerStyle }
              if col == 1 { return statusStyle }
              return cellStyle
              })

              fmt.Println(t)

Three real recipes from a chat TUI

A chat-window layout

Conversation viewport on top, input at the bottom, status bar at the very bottom. Resize-aware. The classic switch / Claude / chat-app shape.

type model struct {
              vp viewport.Model
              input textinput.Model
              width int
              height int
              }

              func newModel() model {
              ti := textinput.New()
              ti.Placeholder = "Type a message..."
              ti.Focus()

              vp := viewport.New(0, 0) // sized later by WindowSizeMsg
              return model{vp: vp, input: ti}
              }

              var (
              paneStyle = lipgloss.NewStyle().
              Border(lipgloss.RoundedBorder()).
              BorderForeground(lipgloss.Color("#2A3140")).
              Padding(0, 1)
              statusStyle = lipgloss.NewStyle().
              Foreground(lipgloss.Color("#8B8F9A")).
              Padding(0, 1)
              )

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              switch msg := msg.(type) {
              case tea.WindowSizeMsg:
              m.width = msg.Width
              m.height = msg.Height
              m.vp.Width = msg.Width - 4 // account for border + padding
              m.vp.Height = msg.Height - 6 // account for input + status
              m.input.Width = msg.Width - 6
              case tea.KeyMsg:
              if msg.String() == "ctrl+c" { return m, tea.Quit }
              }

              var c1, c2 tea.Cmd
              m.vp, c1 = m.vp.Update(msg)
              m.input, c2 = m.input.Update(msg)
              return m, tea.Batch(c1, c2)
              }

              func (m model) View() string {
              return lipgloss.JoinVertical(lipgloss.Left,
              paneStyle.Render(m.vp.View()),
              paneStyle.Render(m.input.View()),
              statusStyle.Render("ctrl+c quit"),
              )
              }

A loading state during async work

Spinner while loading, content when done. The pattern for any async UI.

type chatLoadedMsg struct{ chats []Chat }

              type model struct {
              spin spinner.Model
              loading bool
              chats []Chat
              }

              func loadChats() tea.Cmd {
              return func() tea.Msg {
              chats := api.FetchChats() // expensive
              return chatLoadedMsg{chats}
              }
              }

              func (m model) Init() tea.Cmd {
              return tea.Batch(m.spin.Tick, loadChats())
              }

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              switch msg := msg.(type) {
              case chatLoadedMsg:
              m.loading = false
              m.chats = msg.chats
              return m, nil
              case spinner.TickMsg:
              var cmd tea.Cmd
              m.spin, cmd = m.spin.Update(msg)
              return m, cmd
              }
              return m, nil
              }

              func (m model) View() string {
              if m.loading {
              return m.spin.View() + " loading chats..."
              }
              return renderChats(m.chats)
              }

Multi-pane focus with Tab

Tab cycles focus. Whichever pane is focused gets a coral border and the keystrokes.

type pane int
              const ( paneList pane = iota; paneInput )

              type model struct {
              list list.Model
              input textinput.Model
              focus pane
              }

              var (
              blur = lipgloss.NewStyle().Border(lipgloss.RoundedBorder()).
              BorderForeground(lipgloss.Color("#2A3140"))
              focus = lipgloss.NewStyle().Border(lipgloss.RoundedBorder()).
              BorderForeground(lipgloss.Color("#FF7849"))
              )

              func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
              if k, ok := msg.(tea.KeyMsg); ok && k.String() == "tab" {
              m.focus = (m.focus + 1) % 2
              return m, nil
              }

              var cmd tea.Cmd
              switch m.focus {
              case paneList: m.list, cmd = m.list.Update(msg)
              case paneInput: m.input, cmd = m.input.Update(msg)
              }
              return m, cmd
              }

              func styleFor(p, current pane) lipgloss.Style {
              if p == current { return focus }
              return blur
              }

              func (m model) View() string {
              return lipgloss.JoinHorizontal(lipgloss.Top,
              styleFor(paneList, m.focus).Render(m.list.View()),
              styleFor(paneInput, m.focus).Render(m.input.View()),
              )
              }
